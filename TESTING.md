# StableMate Testing Documentation

This document describes the automated testing suite used to validate the functionality of the StableMate console application.  
All tests are black-box simulations using scripted input files that mimic real user behavior.

**Environment Note:**  
All test commands were executed in Windows PowerShell.

---

# 1. Overview

StableMate includes a full suite of automated input tests located in the `/testing` directory.  
Each test file contains a sequence of menu commands and inputs, allowing StableMate to be tested without manual typing.

This system verifies:

- Menu navigation  
- CRUD operations for Riders, Horses, and Lessons  
- File-based data persistence  
- Input validation for incorrect, malformed, or extreme values  
- Stable settings editing  
- Care queue ordering & overdue logic  
- Behavior under full program flow  

Test files make the program fully testable, repeatable, and easy to validate.

---

# 2. How to Run Tests

All tests must be executed from inside the `terminal/` folder, because StableMate loads data from `../data`.

Navigate to the folder:

```powershell
cd finalcs2-SoMuchMaddy/terminal
```

And use the command structure: 

```powershell
gc ..\testing\test_EXAMPLE.txt | java StableMate
```

---

# 3. Data Baseline Reset System

StableMate uses two data directories: /data is the live working data and /data_baseline is a clean snapshot used for resetting

Between tests, reset the data folder to ensure consistent results:

```powershell
cd finalcs2-SoMuchMaddy
Copy-Item .\data_baseline\* .\data -Force
cd .\terminal
```

Program navigates to the "Add Rider" menu.

User enters the rider's details.

Rider is added with a unique autogenerated ID.

The new Rider is appended to riders.txt.

**Expected Change in Data:**

Valid phone number

Correct age

Valid Rider ID

**Expected Change in Data:**

Remaining records and IDs stay unchanged.

**Remove everything test:**

**Behavior Verified:**

Sequentially removes all Riders, Horses, and Lessons.

Program does not crash even when lists become empty.

**Expected Change in Data:**

riders.txt, horses.txt, and lessons.txt are emptied.

This test should be run last, followed by a baseline reset.

- Reject input  
- Display an error  
- Ask again
